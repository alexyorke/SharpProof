# NuGet developer-experience audit coverage

This ledger reconciles the supplied architectural audit with the actual repository. The audit's unit is a deduplicated recommendation, including its architectural premise. The universe is the supplied audit's installation, configuration, host/TFM, documentation, symbols, reproducibility, provenance, metadata and API-governance recommendations; repeated roadmap entries are grouped below. An implementation or workflow definition is not evidence that its tests, release-account setup, publication or rendered preview succeeded. Final qualification must identify the exact source/artifacts and completed checks.

The audit describes an older architecture and several APIs/tools absent from this checkout. The current graph is `SharpProof -> SharpProof.Verifier -> SharpProof.Attributes`: main is the metadata-only standard entrypoint, Verifier owns analysis/build/native tools, and Attributes supplies the supported application API. New consumers author one main-package reference without activation properties. Preview package availability remains a feed/release fact.

| Handle NuGet repository signatures and changed outer digests | **Separate verification domains; do not rewrite evidence casually.** Verify NuGet's repository signature through NuGet's supported signature tooling, and verify GitHub attestations against the exact attached release asset bytes. Repository signing can change the ZIP's outer digest from the packed/attested bytes. A digest mismatch is not resolved by silently stripping signatures or substituting another artifact; document provenance and preserve original bytes. |
| Pin Actions and add a GitHub test logger | **Pins retained; extra logger not added as a correctness gate.** [CI](../.github/workflows/ci.yml) and [package workflow](../.github/workflows/package-consumers.yml) use full commit pins. A logger remains an optional annotation enhancement if a concrete reporting gap is demonstrated, preserving identities/filter/failure semantics and avoiding raw-log uploads. No new logger package or annotation guarantee is claimed. |
