# C# language and modeled behavior reference

SharpProof reasons about selected C# behavior using compiler evidence, typed intermediate representation (IR), conservative effects, and bounded native verification. This reference describes the implemented cases and their boundaries. It does not claim complete C# language support.

Use [public API](public-api.md) for contract syntax, [coverage and limits](coverage-and-limits.md) for the overall boundary, [analysis limits](analysis-limits.md) for budgets, and [Unknown reasons](unknown-reasons.md) when an individual claim cannot be decided.

## How to read support

| Surface or term | Meaning |
| --- | --- |
| Portable analyzer | Validates declarations and contracts, reports conservative effects, and uses advisory abstract domains. An analyzer diagnostic or its absence is not a native proof verdict. |
| Native verifier | Checks individual claims over admitted compiler artifacts, using the qualified Linux amd64 container. Exact frontend lowering is necessary for many checks but does not itself establish a claim. |
| Exact modeled operation | The admitted shape preserves its modeled values, faults, and ordering. Subsequent solver, loop, call, witness, or resource limits can still produce Unknown. |
| Opaque value or call | Its details are unavailable. Conservative effects and approximation values preserve uncertainty; an unrelated claim can sometimes still be proven. |
| Closed boundary | The unsupported shape is rejected or remains Unknown. It must not silently become an assumption that establishes the claim. |

Admission is specific to an operation, type, compiler shape, and claim. Contract predicates and executable bodies have different routes: a body can call an admitted source helper while the same arbitrary invocation is unavailable inside a pure contract predicate. Likewise, discovering an allocation or synchronization effect does not establish an exact result relation.

The coarse [operation inventory](../src/SharpProof.Frontend/CSharpOperationSemantics.Operations.cs) is not a standalone feature matrix. CFG lowering can handle constructs marked incomplete in that inventory, and body-specific rules can recognize narrower forms. The [expression lowerer](../src/SharpProof.Frontend/RoslynTotalExpressionLowerer.cs), [program lowerer](../src/SharpProof.Frontend/RoslynTotalProgramLowerer.cs), and their operation rules determine actual admission. The linked behavioral tests below specify concrete exercised cases; they are regression evidence, not universal language guarantees.

## Evidence-backed example

The method body below is an existing behavioral test case in [TypedLoopLoweringTests](../src/SharpProof.Frontend.Tests/TypedLoopLoweringTests.cs). Its compiled and lowered executions are compared for input `7`, yielding `9`. The class wrapper makes this a complete compilation unit; documentation snippet compilation is also checked by the repository's documentation tests:

```csharp
public static class LoopExample
{
    public static int Target(int x)
    {
        for (int i = 0; i < 3; i++)
        {
            if (i == 1) continue;
            x++;
        }
        return x;
    }
}
```

This example establishes the tested execution behavior. To request a universal postcondition or effect verdict, add a valid contract and inspect that individual native claim; a correct execution example does not replace that proof obligation.

## When an apparently supported case is Unknown

Check the selected callable and individual claim before changing the program. A type can be admitted while its operator is not; an effect can be recognized while the result remains opaque; an exact callee can still lack replayable source-site evidence. Loop invariants, aliasing, initialization, generic instantiation, unsupported predicate evaluation, compiler elision, and expression/call/solver budgets can each change the outcome.

The worker must not publish Refuted solely from an abstract possible failure. Approximation-dependent paths, impossible aliases, unevaluable external results, or missing concrete witnesses can require Unknown. Proven applies only to the recorded claim under its recorded assumptions and vacuity, not to every behavior of the method. Consult [semantics](../SEMANTICS.md), [SMT lifecycle](smt-lifecycle.md), and [Unknown reasons](unknown-reasons.md) for those outcome requirements.
