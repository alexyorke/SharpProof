# Analyzer reduction review

Scope: `SharpProof.Analyzer`, `SharpProof.Analyzer.Core`, and related analyzer tests. Read-only inspection; no production or test code was changed.

## Conclusion

No unused production types or methods were identified. The public analyzer entry point in `SharpProof.Analyzer/SharpProofAnalyzer.cs` is a thin, necessary Roslyn adapter, and `IAnalyzerSessionFactory` is intentionally used by production and test hosts. The worthwhile reductions are local deduplication and boilerplate extraction, estimated at about 300 LOC, with roughly 250 LOC high confidence.

## Recommended reductions

1. **Factor sequential descendant traversal** (`SharpProof.Analyzer.Core/RequiresCallSiteDiscovery.cs:1660-1990`, about 100 LOC). Thirty recursive call sites repeat the same `foreach` plus `MayCompleteNormally` bail-out. A local `WalkSequential` iterator can preserve ordering and stop semantics. Validate with the nested requires-call-site and replay-soundness suites.

2. **Reuse the existing switch-pattern lattice** (`RequiresCallSiteDiscovery.cs:2172-2385` and `SharpProof.Effects/SwitchExpressionFacts.cs:459-520`, about 60 LOC). The `Negate`, `And`, and `Or` logic is duplicated. First share only the lattice operations and compare behavior; then consider moving the evaluator. Do not drop `MatchTypePattern`: it uses `ClassifyCommonConversion`, while the Effects implementation uses `IsTotalPattern`, so that branch needs an explicit compatibility design.

3. **Table-drive `MatchTypePattern` special types** (`RequiresCallSiteDiscovery.cs:2251-2285`, about 28 LOC). The runtime-type-to-`SpecialType` switch is pure and self-contained; a static map can retain the null/error fallback behavior.

4. **Extract candidate add-or-upgrade logic** (`RequiresCallSiteDiscovery.cs:218-253`, `:277-297`, `:317-355`, about 35 LOC). The candidate construction and replacement policy are repeated; parameterize only the differing span predicate.

5. **Delegate anonymous-function discovery** (`RequiresCallSiteTreeAnalyzer.cs:1575-1586`, `:1620-1634`, about 13 LOC). `GetAnonymousFunctions` duplicates `ReachableOperations` and only adds `OfType<IFlowAnonymousFunctionOperation>()`.

6. **Centralize incomplete-analysis diagnostics** (`AnalyzerFeaturePipeline.cs:162`, `:273`, `:403`, `:433`, about 18 LOC). Four reports repeat location/name/reason construction. A private reporting helper should preserve the exact generated descriptor and reason text.

7. **Share validation diagnostic helper and simplify companion DTO** (`ContractForValidation/ContractForCompanionValidator.cs:238-246`, `ContractForValidationEngine.cs:212-219`, `:237-248`, about 14 LOC). The `At` wrappers are identical. `ResolvedCompanion` is immutable storage with no custom equality and is a candidate for a positional record.

8. **Share single-match tail** (`PrimaryConstructorCallableInventory.cs:6-68`, about 10 LOC). Both lookup methods differ in filtering/pre-checks but have identical cardinality validation and normalization.

9. **Inline `DescribePlacement`** (`AnalyzerFeaturePipeline.cs:782-802`, about 5 LOC). It has one caller and only forwards to the generated catalog method.

10. **Compact analyzer configuration carriers** (`Configuration/AnalyzerConfiguration.cs:3-33`, `AnalyzerConfigurationOptionRegistry.cs:29-37`, about 16 LOC). The option is an internal immutable data carrier suitable for a positional record; configuration properties can be compacted without changing behavior.

## Tests

The largest test-only opportunity is consolidating repeated diagnostic-ID assertions into the existing analyzer test-host helper pattern: 191 repeated projection blocks were reported across analyzer tests, worth about 380 LOC. A second safe extraction is the repeated seven-line `Positive` fixture preamble in `NestedRequiresCallSiteTests.cs` (26 of 36 literals, about 155 LOC). Both changes should preserve source literals and assertion constraints exactly.

## Caveats and order

- Generated diagnostic catalogs and generated model files should be changed only through their generators or source schema.
- Keep the `MatchTypePattern` conversion semantics explicit; this is the main behavioral risk.
- Apply mechanical local helpers first, then lattice sharing, then any cross-assembly API visibility changes.
- Run the repository-prescribed targeted analyzer tests before the broader analyzer/effects test gates.
