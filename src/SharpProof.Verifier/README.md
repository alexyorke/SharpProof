# SharpProof.Verifier

Verifier is SharpProof's implementation package and a compatibility entrypoint. New users should install the main **SharpProof** package once; it restores Verifier and Attributes at exact matching versions and enables full strict verification without activation properties.

Verifier owns portable Roslyn analysis, companion validation, compiler-artifact capture, MSBuild tasks, launcher/worker, and pinned architecture-specific Z3 libraries. These are build tools, not supported application compile APIs. The Attributes dependency supplies the application contract API; preserve that dependency when packing libraries. Native worker/solver payloads must stay out of downstream application runtime output.

Tooling assemblies embed portable PDBs and compile sources so symbols travel with the actual Roslyn/MSBuild/worker binary. Matching symbol-package and coverage PDBs are extracted from that same build. This improves offline inspection without guaranteeing that every debugger or stack trace displays source lines; see [NuGet debugging](https://github.com/alexyorke/SharpProof/blob/f76a00dfc87dc9ecd4dcd1fc38d2c71f92815833/docs/nuget-debugging.md).

Full verification requires a compatible .NET 10 SDK/runtime. Native execution covers Windows, macOS, and glibc Linux on x64/ARM64 under the [host and filesystem support boundary](https://github.com/alexyorke/SharpProof/blob/f76a00dfc87dc9ecd4dcd1fc38d2c71f92815833/docs/preview-support.md). Windows solver payloads link their C++ runtime statically. musl and unlisted platforms are unsupported. Core MSBuild and Windows full-framework MSBuild hosting have distinct [qualification limits](https://github.com/alexyorke/SharpProof/blob/f76a00dfc87dc9ecd4dcd1fc38d2c71f92815833/docs/legacy-compatibility.md); interactive IDE behavior is a separate boundary.

The worker publishes matching request/result/compiler-manifest evidence and reports selected claims, Proven/Refuted/Unknown counts, incomplete coverage, assumptions, vacuity, timing, and cache status. A replayable refutation fails the build. Unsupported selected code remains Unknown/incomplete; it must not silently fall back to a successful unverified build. Explicit advisory/off settings are deliberate policy choices.

The optional [SharpProof.Tool](https://github.com/alexyorke/SharpProof/blob/f76a00dfc87dc9ecd4dcd1fc38d2c71f92815833/SharpProof.Tool/README.md) can explain a stored result; it does not run a new proof or establish current-source freshness. Public release [SBOM/provenance evidence](https://github.com/alexyorke/SharpProof/blob/f76a00dfc87dc9ecd4dcd1fc38d2c71f92815833/eng/release/README.md) binds published original assets separately from NuGet repository signatures. Attributes strong naming provides compatibility identity and does not authenticate a publisher.

Use [configuration](https://github.com/alexyorke/SharpProof/blob/f76a00dfc87dc9ecd4dcd1fc38d2c71f92815833/docs/configuration.md), [reading results](https://github.com/alexyorke/SharpProof/blob/f76a00dfc87dc9ecd4dcd1fc38d2c71f92815833/docs/verification-results.md), and [Unknown reasons](https://github.com/alexyorke/SharpProof/blob/f76a00dfc87dc9ecd4dcd1fc38d2c71f92815833/docs/unknown-reasons.md). Local binlogs and evidence may contain source, paths and evaluated secrets; follow [support redaction guidance](https://github.com/alexyorke/SharpProof/blob/f76a00dfc87dc9ecd4dcd1fc38d2c71f92815833/docs/support.md) before sharing. The runtime/solver/protocol closure is validated as a unit; do not mix worker binaries, native libraries, or contract API versions.
