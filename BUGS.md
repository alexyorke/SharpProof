# Bug backlog

70 open bugs, reprioritized by impact, reachability, and affected scope.

Priority definitions:

- **P0 - Critical:** Can make a false proof or refutation trusted, or break verification/publication integrity.
- **P1 - High:** Can produce a wrong supported-workflow result, hide a mandatory check, or broadly crash, hang, or lose authoritative results.
- **P2 - Medium:** Usually fails closed or causes false positives, incomplete diagnostics, bounded reliability problems, or narrower correctness errors.
- **P3 - Low:** Minor precision, canonicalization, test, documentation, or low-impact operational issue.

## P0 - Critical (45)

- **BUG-010 [P0] - Bind-mount aliases bypass publication-set exclusivity:** LinuxPathIdentity derives publication locks and marker identities from normalized path strings rather than physical filesystem identity. Two bind-mount aliases can acquire independent leases for the same destination, allowing concurrent replacement, deletion, or rollback into mixed published state.
- **BUG-022 [P0] - Compiler reference hashes are not bound to consumed PE images:** CompilerProbeSnapshot cannot hash image-backed references and independently reopens file-backed paths after Roslyn may have cached different metadata. Its artifact can therefore identify different reference bytes than the compilation actually consumed.
- **BUG-030 [P0] - Container contract validation omits required schema fields:** ContainerContract validates only part of the generated marker and accepts missing, changed, duplicate, or unknown runtime and image identity fields. Preflight can certify a stale or conflicting environment contract that disagrees with repository pins.
- **BUG-033 [P0] - Corpus importer attributes ignored files to the pinned commit:** OpenSourceCorpusImporter trusts clean git status but enumerates all on-disk C# files, including ignored untracked files. Such files can change corpus compilation and analyzer verdicts while the manifest falsely attributes the input to the pinned upstream commit.
- **BUG-045 [P0] - Effect replay trusts self-asserted event semantics:** CompilerEffectClaimArtifactCodec validates replay event geometry and self-derived hashes but does not bind the asserted operation kind or identities to compiler semantics at the source span. A canonical artifact can fabricate an allocation event and obtain an accepted replay-backed effect refutation.
- **BUG-052 [P0] - Final compilation snapshots erase source checksum metadata:** The final-compilation snapshot hashes source characters as UTF-8 and omits original encoding, checksum algorithm, and Roslyn checksum. Compilations with different PDB or source-provenance inputs can receive identical evidence, so the artifact cannot faithfully attest emitted debugging metadata.
- **BUG-053 [P0] - Final compilation snapshots omit diagnostic policy:** The final-compilation snapshot omits general and per-ID diagnostic policy, warning level, and suppressed-diagnostic reporting. Distinct compiler configurations can produce identical attestation artifacts, allowing the package oracle to certify the wrong build behavior.
- **BUG-057 [P0] - Fuzz decoder integration check passes without decoder use:** FuzzRunnerEvidenceTests searches the campaign script for a decoder name that is already present in a dot-sourced filename. Removing or bypassing the actual strict decoder call leaves the gate green and can admit malformed runner JSON into campaign evidence.
- **BUG-073 [P0] - Linux backslash paths collide in compiler provenance:** CompilerProbeSnapshot unconditionally rewrites backslashes to slashes, although backslash is a legal Linux filename character. Distinct syntax, reference, or additional-file paths can therefore serialize identically and authenticate the wrong compiler input.
- **BUG-077 [P0] - Malformed UTF-16 collapses protocol identity fields:** Worker protocol validation accepts lone surrogate code units that UTF-8 and JSON replace with U+FFFD. Distinct paths, IDs, locations, or assumption authorities can serialize and hash identically, so authenticated protocol identities are not injective or round-trip faithful.
- **BUG-079 [P0] - Manual support review survives semantic context changes:** OpenSourceCorpusImporter reuses support decisions by a method-declaration hash that excludes containing type, namespace, imports, path, and source commit. Identical text moved into a different semantic context can inherit an obsolete review status and silently invalidate coverage claims.
- **BUG-087 [P0] - MSBuild omits exact-invocation result validation:** The shipped verifier target never supplies InvocationResultPath to ValidatePublishedVerificationResult, so private per-invocation binding checks are skipped. Concurrent builds sharing publication paths can accept and advertise another invocation's internally valid verification evidence.
- **BUG-088 [P0] - Mutable runtime paths invalidate containment authentication:** RunVerifier reduces the dotnet host and supervisor assembly to mutable pathnames before launch, without durable byte identity. Replacement between validation and launch can make lifecycle receipts describe code that did not enforce descendant cleanup.
- **BUG-108 [P0] - Portable member semantic IDs are not bound during canonical decoding:** PortableIrGraphCodec restores artifact-supplied documentation IDs after canonical re-encoding instead of binding them to declaring type, name, and signature. A shape-compatible call can impersonate an approved API and receive its specification, yielding an unsound proof.
- **BUG-110 [P0] - Postcondition authority accepts vacuity labels without proving vacuity:** CompilerResponseEvidenceAuthority validates contradictory-precondition and no-normal-return claims through label membership alone, without establishing inconsistency or body noncompletion. A corrupt response can convert a real postcondition counterexample into an accepted vacuous Proven result.
- **BUG-115 [P0] - Publication ancestor replacement is not detected:** LinuxPathIdentity compares canonical path strings while discarding directory device and inode identities. Replacing a writable ancestor can split locks from publication markers and redirect output into another directory tree.
- **BUG-118 [P0] - Qualification receipts can bind different evidence generations:** Write-SharpProofQualificationReceipt validates one JSON generation, then reopens the mutable pathname later for length and hashing. Atomic replacement between those operations can produce a passed receipt whose digest authenticates an unvalidated generation that release publication accepts.
- **BUG-119 [P0] - Qualification receipts trust self-asserted gate evidence:** Qualification receipt creation trusts shallow caller-supplied JSON fields without proving the named gate ran or validating gate-specific semantics. A passed release qualification can be minted for unexecuted or failed acceptance, configuration, coverage, mutation, or consumer gates.
- **BUG-134 [P0] - Release evidence omits executable package build files:** Package payload validation authenticates only DLL and SO entries, leaving shipped props, targets, catalogs, and other executable or behavioral files unbound. Substitution before evidence generation becomes self-authenticated by the resulting archive hash and can reach release publication.
- **BUG-136 [P0] - Requested SARIF output is not validated:** The MSBuild validation task exposes but never validates the requested SARIF path, and the target does not pass it. Builds can advertise successful verification while consumers receive missing, stale, malformed, or cross-run SARIF.
- **BUG-143 [P0] - Source Link is accepted on the wrong metadata parent:** SharpProof.SymbolPackageValidator locates Source Link custom debug information by kind but never requires its parent to be the module. It can certify a symbol package whose Source Link blob exists on a document or method and is undiscoverable by debuggers.
- **BUG-144 [P0] - Source Link mappings may cover no documents:** SharpProof.SymbolPackageValidator checks mapping syntax but never applies Source Link semantics to actual PDB documents. A release can pass with no nonembedded document resolvable for stepping or source download.
- **BUG-146 [P0] - Source-location authority is not bound to claim ownership:** CompilerManifestArtifact validates owner and location pairs against mutable manifest rows and source geometry but never independently binds a predicate or callable to that span. Resealed evidence can report a verified claim at another valid source location while passing authority checks.
- **BUG-147 [P0] - Specification packs trust unverified public-sign metadata:** CompilerSpecificationPackProvider accepts assemblies by name, public-key token, and API shape without binding a private-key signature or module identity. A matching but unrelated assembly can attach approved specifications to different implementations and produce unsound proofs.
- **BUG-148 [P0] - Staged NuGet packages can change before push:** Publish-SharpProofRelease hashes a staged package, closes it, and later passes only its pathname to dotnet nuget push. An atomic same-user replacement in the writable staging directory can upload bytes different from every validated hash and publication-plan entry.
- **BUG-152 [P0] - Symbol validation accepts nonportable CodeView identities:** SharpProof.SymbolPackageValidator applies portable-PDB Guid and Stamp rules to any CodeView record without requiring the portable marker or Age 1. It can certify a PE/PDB pair that consumers interpret as Windows PDB identity and cannot resolve from the published symbol package.
- **BUG-158 [P0] - Unsupported hosts retain stale verification publications:** SharpProof.Verifier conditions both normal invalidation and Clean reset on a supported verifier host. Building or cleaning a previously verified shared tree on an unsupported host leaves old requests, results, manifests, SARIF, and markers appearing current.
- **BUG-162 [P0] - Void replay accepts arbitrary return values:** CallableCounterexampleReplayer and CompilerLoweredArtifact do not require a void callable's execution return value to be null. Malformed IR can return an arbitrary value and still produce a replay-accepted fabricated refutation and false build failure.
- **BUG-167 [P0] - Worker performance evidence is not bound to measured binaries:** WorkerPerformanceProbe measures mutable Worker and Launcher assemblies but records no paths, hashes, or module identities for them. Stale or substituted compatible binaries can certify the current source commit while the evidence envelope remains unchanged.
- **BUG-169 [P0] - Z3 validation and native loading race on file replacement:** SharpProof.Host hashes the Z3 library by pathname, closes the stream, and later reopens that path for native loading. Replacement between those operations can load unverified bytes and defeat native-payload integrity.

## P1 - High (25)

- **BUG-175 [P1] - Approved repository origin relies on unauthenticated local metadata:** OpenSourceCorpusImporter accepts an editable local origin URL without proving that the checked-out commit belongs to the approved remote. An arbitrary clean repository can be imported and attributed to the approved upstream.
- **BUG-176 [P1] - Atomic replacement discards destination access metadata:** AtomicFile replaces an existing destination with a fresh staging inode without copying Unix mode, ACLs, or extended metadata. Rewriting a restricted output can change administrator-selected access policy, including widening its file mode under a permissive umask.
- **BUG-187 [P1] - Concurrent fuzz campaigns overwrite shared evidence:** Fuzz campaign scripts use one fixed output namespace without a lease or run-specific staging directory. Overlapping runs can delete, truncate, mix, or overwrite each other's active outputs and campaign summaries.
- **BUG-190 [P1] - Cooperative timeout can leave worker descendants running:** LinuxWorkerProcess sends SIGTERM only to the direct child and skips the process-tree kill when that child exits during grace. Surviving descendants can continue consuming resources or producing side effects after timeout is reported.
- **BUG-202 [P1] - Fallback cleanup can kill descendants of a reused PID:** Verifier fallback cleanup scans descendants using a recycled numeric supervisor PID without binding it to the retained pidfd. After PID reuse it can SIGKILL descendants of an unrelated process.
- **BUG-206 [P1] - Generated code bypasses soundness enforcement:** The SharpProof soundness analyzer disables generated-code analysis, so mutable static storage and unsafe semantic-cache writes in generated components bypass SPMETA002 and SPMETA010. Mutable generated policy arrays can alter operation admission across compilations without enforcement.
- **BUG-210 [P1] - Imported bytes are not bound to the recorded commit:** OpenSourceCorpusImporter records HEAD and status before reading mutable worktree bytes, while status can omit specially flagged files and races later edits. Modified bytes can be hashed under provenance for a different commit.
- **BUG-213 [P1] - Indirect dispatch bypasses forbidden API analysis:** SharpProofSoundnessAnalyzer inspects direct invocation targets but not captured method references or dynamic invocations. Soundness-critical forbidden APIs can execute through delegates or dynamic dispatch without the mandatory SPMETA001 diagnostic.
- **BUG-216 [P1] - Interrupted cache transactions evade recovery and size limits:** VerificationCache leaves rollback and eviction files under noncanonical names after interruption, while future scans ignore them. Exact-key data can remain missing, transaction artifacts can grow beyond MaximumBytes, and stale counterexamples persist indefinitely.
- **BUG-217 [P1] - Invocation paths can alias compiler outputs:** InvalidatePublishedResult checks publication paths against compiler outputs but omits invocation request, result, and manifest paths. The launcher can consequently overwrite or delete a compiler-owned assembly, PDB, or other output through an equal or hard-linked invocation path.
- **BUG-219 [P1] - Lexical containment follows out-of-tree license symlinks:** Corpus import containment checks normalize lexical paths without resolving symlink or reparse targets. Reads and writes can follow an apparently contained path outside the repository, including an external mutable license or output directory.
- **BUG-227 [P1] - MIT provenance accepts appended license restrictions:** OpenSourceCorpusImporter accepts any license text beginning with the MIT header and records it as SPDX MIT without validating the complete reviewed terms. Upstream restrictions can therefore enter the corpus under incorrect provenance.
- **BUG-248 [P1] - Publication reset checks state before acquiring locks:** LinuxPathIdentity.ResetPublicationSet examines markers and outputs before taking publication locks. It can report success while a concurrent publication later completes or fail spuriously on a legitimate partial marker set.
- **BUG-249 [P1] - Publication rollback snapshots are unbounded in memory:** Worker Launcher captures every preexisting publication member with File.ReadAllBytes and retains all payloads in memory without protocol size limits. Large destination files can cause proportional allocation and process OOM before publication begins.
- **BUG-252 [P1] - Release configuration checks only the first REST page:** The release-configuration checker calls paginated GitHub REST list endpoints without pagination or page iteration. Rows beyond page one can be ignored, allowing an incomplete exact-set check to pass or falsely fail.
- **BUG-253 [P1] - Release publishing cannot resume after a partial push:** Publish-SharpProofRelease performs irreversible package and symbol pushes sequentially, but preflight rejects any already-present main package on retry. A transient mid-release failure can strand an immutable partial version that automation cannot complete.
- **BUG-254 [P1] - Replaceable cache lock permits concurrent transactions:** VerificationCache locks an inode but validates only the replaceable lock pathname, so another process can rename it and create a separately locked replacement. Two transactions can then run concurrently and lose entries, misstage capacity, or strand artifacts.
- **BUG-255 [P1] - Repository allowlist normalization removes internal .git text:** OpenSourceCorpusImporter removes every .git occurrence from repository URLs instead of only a terminal suffix. An unapproved lookalike origin can normalize to an allowlisted repository and supply corpus source and license material.
- **BUG-256 [P1] - Runtime snapshot can mix old dependencies with new files:** WorkerBinaryIdentity parses dependencies from one open deps file but later stages and hashes components reopened by pathname. Atomic replacement can seal a closure whose staged deps and component set disagree, causing launch or load failure.
- **BUG-270 [P1] - Supervisor death leaves verifier descendants uncontained:** The launcher lacks a parent-death signal, and cleanup cannot reach its reparented process group after abrupt supervisor death. The verifier can survive containment failure and continue consuming resources or producing side effects.
- **BUG-271 [P1] - Supervisor retries incomplete descendant cleanup forever:** VerifierProcessSupervisor converts a bounded incomplete cleanup result into an unbounded retry loop with no deadline, retry cap, or cancellation exit. Persistent cleanup failure can leave the supervisor, descendants, handles, and retained cleanup anchor alive indefinitely.
- **BUG-272 [P1] - Symbol validation ignores the portable-PDB checksum:** SharpProof.SymbolPackageValidator compares CodeView with the mutable PDB header ID but ignores the PE PdbChecksum record. Altered sequence points or documents can be certified even when checksum-aware consumers reject the package or display misleading mappings.
- **BUG-281 [P1] - Validated fuzz output paths remain replaceable before publication:** The fuzz validator hashes bytes from an open snapshot but the campaign records that hash beside the original mutable path. Replacement after validation can publish a summary describing different bytes than the cited stdout artifact.
- **BUG-285 [P1] - Worker timeout can signal a reused process ID:** LinuxWorkerProcess checks a managed process for exit and later sends SIGTERM through its numeric PID without retaining process identity. If the PID is recycled in that window, timeout or disposal can terminate an unrelated process while reporting a normal worker timeout.
- **BUG-286 [P1] - Z3 resolver becomes visible before the verified handle:** ContainerNativeLibrary registers the DllImport resolver before publishing the verified Z3 handle. A concurrent first P/Invoke can observe zero and fail binding or fall back to ambient library probing.
